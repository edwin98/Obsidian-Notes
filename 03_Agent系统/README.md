# Agent 系统：业务说明与技术实现

这套文档讨论一个问题：**已有脚本会跑测试了，Agent 还能替工程师做什么？**

我们的答案是：测试失败以后，让它接着帮忙查。它可以换条件重跑、比较新旧版本、找出怎样才能复现、整理日志，最后把清楚的复现步骤和调查结果交给工程师。

原来的按需测试也保留。用户可以直接说：

> “帮我测一下这个版本。”

也可以说：

> “升级以后，手机移动时视频偶尔卡住，帮我查查。”

两种要求从同一个输入框进入，由系统判断接下来做什么。

## 这次融合后的读法

各章前半部分先用具体问题解释用途，后半部分再展开数据结构、接口、运行约束和设计依据。读懂业务以后，可以在同一章继续追到技术细节，不需要返回旧版拼接方案。

全文以**统一入口、按需测试、多轮异常调查、修复验证**为当前主线。旧版的工具调用、状态保存、异常处理、统计评测和 SFT/DPO 原理继续使用，但示例改成新版任务。旧版单次测试图不再代表新版的全部架构。

技术段落采用两个口径：**设计约定**说明新版 Agent 应怎样工作；**教学示例**用具体结构、数字和伪代码解释机制。示例不表示生产实测，也不要求现有 `code/` 已经实现。文档是本轮的主要交付物，代码仅作可选学习参考。
