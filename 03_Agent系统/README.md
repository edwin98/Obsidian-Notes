# Agent 系统：业务说明与技术实现

## 一、直观理解

这套系统既接受“帮我测一下这个版本”，也接受“升级后移动视频偶尔卡住，帮我复现”。前者完成约定测试并交付结果，后者根据实验结果安排对照、简化和确认，按要求继续检查原因或验证修复。

**先建立完整运行图，再按环节深入。** LLM 理解材料并提出候选，Agent 程序保存任务、检查计划、调用工具和接收结果，测试平台执行动作。三者怎样交互，统一从 [系统运行全流程与交互拓扑](18_系统运行全流程与交互拓扑.md) 开始。

### 建议阅读顺序

1. [00 项目总览](00_项目总览.md)：为什么做，以及模型、程序和工程师如何分工。
2. [18 系统运行全流程与交互拓扑](18_系统运行全流程与交互拓扑.md)：从一条用户消息追到模型输入、工具执行、证据回流与报告。
3. [19 生产级端到端案例](19_生产级端到端案例逐步拆解.md)：从生产理论出发，理解 Agent 与 LLM 的分工、逐轮上下文与工具循环，再看每次参数、返回、事务、异步事件和报告。
4. [20 吞吐验收与 HITL](20_吞吐验收Agent_LLM轮次与HITL安全审计.md)：同一通信项目的按需验收，重点看 11 轮 LLM 交互、审批后目标变更、旧批准失效与安全审计。
5. [17 完整案例](17_完整案例与对外讲述.md)：从用户和业务视角看移动视频卡顿的调查分支。
6. 再按下面的流程索引定位专题，需要实现时读 [代码学习指南](code/学习指南.md)。

### 每篇文档的统一读法

当前正文与代码阅读说明都采用两个部分：

- **直观理解**：用途、具体例子、参与者分工，以及本章在整条链路中的位置。
- **详细技术拆解**：输入输出、数据结构、调用顺序、状态变化、异常分支和实现映射。

只想建立整体印象，可以先读各章第一部分；需要落到设计和代码，再进入第二部分。18 负责贯穿全程，19 逐步拆解异常调查，20 用按需验收展开 LLM 与 HITL，14 负责工程实现，17 负责业务实例，其余章节分别维护各自环节的细节。

### 设计、教学实现与真实接入的边界

正文里的数据契约和架构描述属于设计约定，示例数字用于讲解，不表示生产实测。默认代码使用规则意图器、规则计划器和确定性沙盒；在线模式替换意图与计划的生成方式，执行器仍然是沙盒。真实平台适配、跨进程调度和 MCP 接入按扩展设计理解。

代码仅维护一套任务服务：`task_service.py` 的准备、提交和执行三个阶段构成主线，`task_workflow.py` 复用这些方法表达图路由。命令行、页面和评测使用相同业务方法。代码运行方法见 [代码说明](code/README.md)，模块定位见 [代码文件索引](code/代码文件索引.md)。
