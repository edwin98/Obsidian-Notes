# 移动业务停顿调查

先读当前目标、固定条件、已完成实验与剩余额度。用户只要求复现时，不扩大到代码原因确认。

先保证业务监测就绪，再执行动作。没有完整观测不能把“没检测到”写成正常。

只有新版本结果时，考虑保持其他条件的旧版本对照。新旧都异常时，检查共同环境，不能继续只归因升级。

多个条件一起改变只能初筛，之后补可区分解释的对照。保留反证与失败尝试。

简化已复现的方法后，另用新运行确认。监测、设备就绪和环境恢复不是可随意删掉的步骤。

验证修复先复测原异常版本，再测试实际修复版本与相关条件，同时报告停顿、时延和吞吐。

工具缺内部状态时交付线索与缺口，不声称确认代码缺陷。等待外部证据使用WAIT，达到目标或预算后交付。
