# 大模型微调：SFT (Supervised Fine-Tuning) 核心技术解析

预训练让大语言模型学习语言、知识和代码等基础能力；**有监督微调（Supervised Fine-Tuning，SFT）**则通过输入与目标回答，训练模型按照指令完成任务。

SFT 是大模型指令遵循（Instruction Following）能力的最核心来源，也是目前企业级应用落地最常用、门槛最低的模型定制手段。

---

## 1. 什么是 SFT？与预训练的区别

预训练阶段（Pre-training），模型通常从大量文本中学习预测下一个 token，获得语言、知识和代码等能力。仅具备这种能力，不代表模型就能稳定遵循“请帮我写一封请假条”等用户指令，因此还需要指令微调等训练。

**SFT（有监督微调）则是**：
通过人工（或更强模型）构建高质量的 **(指令, 回复)** 配对数据集，让模型学习在特定的提示词下，应该给出什么样的结构化、符合逻辑的回答。

**类比**：
- 预训练 $\rightarrow$ 读遍全球图书馆，成为了一个上知天文下知地理但思维跳脱的“学者”。
- **SFT $\rightarrow$ 学习“客服礼仪”与“应答规范”，成为一个能听懂人话的好助手**。
- 对齐（RLHF/DPO） $\rightarrow$ 学习人类价值观，避免说错话、教唆犯罪（成为一个安全的助手）。

---

## 2. SFT 的训练数据长什么样？

SFT 需要重视训练数据的准确性、覆盖范围和一致性，不能只追求数量。典型数据结构如下（以 OpenAI 格式为例）：

```json
{
  "messages": [
    {"role": "system", "content": "你是一位拥有资深经验的儿科医生。"},
    {"role": "user", "content": "我的宝宝今天有点轻微咳嗽，并且体温 37.5 度，我该怎么办？"},
    {"role": "assistant", "content": "您好。宝宝目前的情况属于低烧伴有轻微咳嗽。首先...（详细建议）"}
  ]
}
```

这些数据通常包含多轮对话，以及摘要、代码生成、角色扮演和格式转换等指令。训练时，模型根据输入学习目标 Assistant 回复。

---

### 训练目标与数据隔离

SFT 通常最小化目标 token 的交叉熵。若采用 assistant-only loss，system/user 和工具返回 token 常设 labels=-100；是否监督工具调用参数、工具结果和多轮各回答需按目标明确。使用与推理一致的 chat template，确保截断不破坏工具调用边界，padding token 不参与 loss。

数据按源文档、用例/会话及时间分组划分，避免同题改写、相邻切片或 HITL 派生样本同时进入训练与测试。分别评测格式、任务正确性、新知识泛化和通用能力保留。

当前 TRL 提供 `assistant_only_loss` 等配置，依赖聊天模板生成正确的 assistant mask。手工将非目标 token 的 labels 设为忽略值，是另一条实现路线。关键是确认损失覆盖范围，而不是新接口名字；工具结果、用户输入、助手回答的处理也要和训练任务一致。[SFTTrainer 文档](https://huggingface.co/docs/trl/en/sft_trainer)

软件生态上，Trainer 的处理器入口发展为 `processing_class` 等形式。旧示例按当时版本理解，无需为此改动历史项目。[DPOTrainer 文档](https://huggingface.co/docs/trl/en/dpo_trainer)

## 3. SFT 的主流实现手段

对于数百亿参数的模型，全量微调需要为参数、梯度、优化器状态和激活分配较多显存。**PEFT（参数高效微调，Parameter-Efficient Fine-Tuning）**通过减少可训练参数来降低部分训练开销：

### 1. **全参微调 (Full Fine-Tuning，FFT)**
- **原理**：直接将模型的所有权重层解冻，使用 SFT 数据进行完整的反向传播和梯度更新。
- **优点**：可更新全部参数，表达形式不受低秩更新限制；效果仍取决于数据、基础模型和预算，不能预设一定优于 PEFT。
- **缺点**：训练成本和显存需求较高，也可能产生“灾难性遗忘”，即原有通用能力下降。

### 2. **LoRA (Low-Rank Adaptation)**：常见的参数高效微调方法
- **原理**：在原有的庞大 Transformer 模型旁边“旁路”插入两个低秩矩阵（小矩阵）。原模型权重“冻结”不更新。训练时，只更新这两个小矩阵的权重。推理时，将这两个小矩阵的权重加回原矩阵中。
- **优点**：减少可训练参数、梯度和优化器状态，支持多个任务适配器。能否单卡训练仍取决于基座加载、激活、长度和批量，训练参数减少不代表前向成本同比下降。
- **局限**：效果取决于秩、目标模块、数据和任务。LoRA 限制参数更新形式，但不能普遍断言其效果上限低于全参；需在相同评测协议下比较。

#### LoRA 的缩放、参数化与初始化变体

| 方法 | 变化方向 | 核心认识 |
| --- | --- | --- |
| rsLoRA | 缩放 | 从 `alpha/r` 改为 `alpha/sqrt(r)`，研究提高 rank 时的训练稳定性。 |
| DoRA | 参数化 | 将权重的幅度与方向分开处理，增加对更新形式的控制。 |
| PiSSA | 初始化 | 利用原权重中的主成分初始化适配器。 |
| EVA | 初始化 | 利用输入激活中的信息初始化，并分配不同层的适配容量。 |

这些方法并非全部近期才提出。它们作用于不同环节，不能统一理解为“rank 更大的 LoRA”。比较时还应考虑任务效果、训练成本、目标参数与推理限制；旧项目的 LoRA/QLoRA 配置保持原背景。[PEFT 官方 LoRA 文档](https://huggingface.co/docs/peft/v0.21.0/package_reference/lora)

### 3. **QLoRA (Quantized LoRA)**
- **原理**：将冻结的基础模型量化为 4-bit，以减少权重占用的显存，再以较高精度训练新增的 LoRA 参数。
- **优点**：降低显存需求，使部分原先无法在单卡完成的微调变得可行。能否在消费级 24G 显卡上微调 14B 模型，仍取决于序列长度、batch、量化和其他配置。
- **适用场景**：个人开发者或显存预算有限的领域定制任务。

## 4. SFT 最怕什么：灾难性遗忘 (Catastrophic Forgetting)

**症状**：原本一个通用模型，用大量特定领域的专业数据 SFT 了一次之后。虽然领域知识变强了，但突然不会算 1+1 了，也不会用中文正常聊天了。
**原因**：过拟合了那批微调数据，或者原有的通用权重分布被严重破坏。
**解决方案**：
- 根据验证集控制学习率、训练步数和早停；epoch 上限不是固定的 3。
- **混合通用数据集**：在特定领域的数据集里，按照比例掺杂进一部分通用对话、代码生成等高质量数据一起 SFT。

---

## 5. SFT 到底教给了模型什么？（LIMA 的启示）

[LIMA: Less Is More for Alignment](https://arxiv.org/abs/2305.11206) 用 1000 条精心筛选和人工编写构建的高质量 prompt/response，对经过充分预训练的 LLaMA 模型进行 SFT，在其指定的人类与模型偏好评测中取得了较好效果。

**实验支持的结论**：经过充分预训练的模型可用少量高质量数据获得有效对齐。这不能推广为所有模型、领域和任务的定律，也不能证明 SFT 无法学习新知识。预训练提供大量知识与能力，SFT 可改变行为、格式和领域知识表现；新知识的记忆、泛化与遗忘需分别评测。

## 6. SFT 落地常见陷阱与建议

1. **垃圾进，垃圾出 (Garbage In, Garbage Out)**
   错误、低质量或高度重复的数据可能让模型学到错误行为与刻板风格；来源模型名称不能单独代表数据质量。
2. **数据多样性**
   如果在客服训练集中所有问题都是“退货问题”，即使样本很多，也不能保证在“修改密码”等未覆盖场景中可靠。
3. **“强迫症”格式调优优先**
   SFT 可以用于领域行为、指令遵循与输出风格定制。若主要诉求是符合 JSON Schema，还应考虑原生结构化输出或约束解码；不能普遍保证固定数量的 SFT 样本优于其他方式，需按任务评测。结构合法仍不保证事实与业务正确；SFT 与严格 Schema 是互补关系。[结构化输出文档](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses) 详见 [[01_大模型/推理与接口/结构化输出与校验]]。

## 多任务模型与适配器选择

训练了**多个专用小模型**，主干推理仍用通用大模型：

| 模型 | 用途 | 是否微调 |
|------|------|---------|
| Qwen3-32B | 主干推理（用例生成、结果分析） | 否，纯 Prompt |
| gte-multilingual-base 微调版 | 向量化（384维/768维双输出） | 是，领域 SFT |
| gte-reranker 微调版 | 精排（Cross-Encoder 打分） | 是，LoRA |
| Qwen3-4B 微调版 | Query 改写（指代消解 + 问题扩展） | 是，SFT |
| Qwen3-4B 微调版 | 记忆压缩摘要（超出 Token 预算时） | 是，SFT |

**设计理由**：不同任务对模型能力的要求不同——向量化需要语义对齐，改写需要语言理解，两者放在同一模型中会相互干扰且难以独立更新。专用小模型各司其职，延迟低、成本可控，在推理路径上可独立扩容。

## 拒绝采样的数据构建用途

拒绝采样（Rejection Sampling Fine-tuning，RS-FT）是强化学习对齐中的一种数据筛选策略：

1. 对同一个 Prompt，用当前策略模型采样多个回答（如 N = 16 条）
2. 用 Reward Model（或规则打分器）对每条回答评分
3. 只保留得分最高（或超过分数阈值）的回答作为正样本，**拒绝**其余低质量回答
4. 用筛选后的高质量样本对模型做新一轮 SFT 训练

**作用**：将 RL 探索过程中产生的高质量输出转化为有监督训练数据，比纯 PPO 更稳定、实现更简单。核心思想是"采样→评分→筛优→微调"的迭代循环，DeepSeek-R1、LLaMA 的训练流程中均有此环节。

**与 PPO 的区别**：PPO 是在线 RL，每步更新策略并立即利用新策略采样；拒绝采样是离线过滤，先大量采样再筛选，可以并行化，但无法像 PPO 那样在训练过程中动态调整探索方向。
