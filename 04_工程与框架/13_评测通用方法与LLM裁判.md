# 评测通用方法与 LLM 裁判

本页维护 RAG 与 Agent 共用的评测设计方法；业务指标、阈值、数据集与项目流水线保留在各自项目。

## 先明确评测对象

| 对象 | 适用方法 | 必需输入 |
| --- | --- | --- |
| 检索覆盖和排序 | Recall/Hit/MRR/NDCG 等统计 | 查询、实际候选、相关文档标签 |
| 工具与业务动作 | 确定性断言与执行校验 | 实际调用、参数、环境状态与副作用 |
| 报告语义、证据支持 | 固定 rubric 的人工或 LLM Judge | 同一次执行的答案、上下文、参考与轨迹 |
| 可靠性与性能 | 故障场景与负载测试 | 重试恢复、延迟分位数、成本与成功状态 |

指标是否需要 LLM 取决于实现与标签，不仅由指标名称决定。最终回答正确不保证动作执行正确；Faithfulness 只衡量上下文支持，不独立证明事实和版本正确。

## LLM 裁判的校准

固定 Judge 模型、版本、Prompt 和评分锚点；用领域专家数据检查一致性。随机化成对答案顺序，关注位置、长度和风格偏差；记录原始判断，必要时重复评分。模型自报置信度不自动是可靠概率。

领域近似术语应单独检查。自动标签与人工确认标签分开保存；既检查分歧样本，也随机抽查自动接受结果。

## 数据隔离与版本

按源文档、近重复版本、会话或用例分组划分训练与测试；不能只随机打散同题改写。持续检查评测标签是否因知识更新失效。每次运行绑定数据集、模型、Prompt、工具、索引和代码版本。

## 回归与门禁

变更后按受影响模块跑回归，关键业务状态使用断言，非确定性质量使用统计与人工校准。记录样本量、失败分层、延迟和每成功任务成本；不同版本、Judge 或负载下的分数不直接连成基线。

项目中的具体数据集、指标公式与门禁分别见 [[02_RAG系统/11_RAG评测系统]]、[[03_Agent系统/07_Agent评测体系设计]]；相关原始参考来源保留在这两页的框架与裁判章节。
