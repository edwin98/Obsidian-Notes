# Agent面试问答

面试复习页：先口述短答，再进入正文解释机制、例子与失败模式。项目数字和配置只引用 [[02_RAG系统/01_项目事实与实现状态]]、[[03_Agent系统/01_项目事实与实现状态]]，不在本页复制一套未经确认的数值。

## Prompt 设计有什么要点？你觉得 Prompt 优化最有效果的方法是什么？

**短答**：用明确的目标、输入边界、约束、输出要求和少量代表性示例组织 Prompt；用固定评测集比较修改前后的错误类型。

**追问**：如何区分提示词问题、模型能力不足与业务校验缺失？

**正文**：[[01_大模型/03_推理与接口/01_提示词与推理策略]]。

## Human in the loop 是如何做的？权限问题、拒绝回答、澄清等人工介入如何实现？

**短答**：用 checkpoint 保存任务状态，在高危动作、信息不足或需要授权时中断；当前调用返回，审批者通过鉴权后以同一任务恢复。恢复前处理参数校验和副作用幂等。

**追问**：静态断点与动态 interrupt 的恢复方式有什么不同？

**正文**：[[03_Agent系统/06_安全机制与异常恢复]]。

## 模型回答或 Agent 执行过程中，如何插入用户的新消息？

**短答**：应用接收新消息后，可选择排队、取消当前生成后重组上下文，或等 Agent 到达执行边界再处理。下一次模型调用带上有效历史和新约束；用运行 ID 或状态版本隔离旧输出，并处理未完成工具调用与已发生的副作用。普通流式返回不会自动更新当前请求的输入。

**追问**：为什么取消生成不能撤销工具动作？checkpoint 与 KV cache 分别保存什么？

**正文**：[[03_Agent系统/05_记忆与上下文管理#3. 模型对话过程中如何插入新消息]]。

## 如何进行记忆隔离？有什么场景需要用到长期记忆吗？

**短答**：thread_id 标识线程，但应用仍需验证用户和租户归属。当前线程状态由 checkpointer 管理；跨会话偏好与经验由 Store/namespace 管理，知识检索另有授权范围。

**追问**：持久化线程历史为什么仍可属于短期记忆？

**正文**：[[03_Agent系统/05_记忆与上下文管理]]。

## 怎么去测试 Agent 的好坏？怎么去构造 Ground Truth？怎么评估 Agent 的效果？与传统软件测试有什么区别？

**短答**：同时评测结果、工具参数、关键轨迹、安全和成本。确定性业务状态用执行断言，语义报告用校准后的 Judge；Ground Truth 可以允许多条等价有效路径。

**追问**：最终文本正确，为什么仍可能判任务失败？

**正文**：[[03_Agent系统/07_Agent评测体系设计]]。

## 什么是 Prompt 遵从性？怎么提高 Agent 的 Prompt 遵从性？如何提高 Agent 的稳定性？

**短答**：把格式遵循、业务规则与安全约束分别处理：Prompt/训练改善行为，Schema 约束结构，应用校验参数、权限和完成条件；再用回归集验证稳定性。

**追问**：JSON 合法与业务正确的边界在哪里？

**正文**：[[01_大模型/03_推理与接口/02_结构化输出与校验]]。

## Function Calling 和 MCP 有什么区别？两者是什么关系？

**短答**：Function Calling 是模型表达工具名和参数的机制；MCP 规范能力发现与交互；应用仍执行工具并校验授权。二者可以组合，不是同一层的替代品。

**追问**：Skill 与这两者又分别处于哪一层？

**正文**：[[03_Agent系统/03_Function-Calling与消息协议]]。

## ReAct 耗时问题：怎么终止退出思考？怎么避免思考死循环？

**短答**：同时设步骤、时间和调用预算，检测重复动作与连续错误；在硬上限前通过业务路由澄清、降级或转人工。recursion_limit 超限是异常，不会自动执行 HITL。

**追问**：重试如何避免重复产生外部副作用？

**正文**：[[03_Agent系统/06_安全机制与异常恢复]]。

## 讲一下你们 Agent 的架构以及包含的组件，为什么要这么设计？

**短答**：用模型决策、状态图、工具执行、知识检索、安全审批、独立结果判定构成主链路。明确节点与状态，便于观察、恢复与评测；具体生产范围查项目事实表。

**追问**：LLM 与确定性代码分别负责什么？

**正文**：[[03_Agent系统/00_项目总览]]。

## 框架选型：为什么选择 LangGraph 而不选择其他的（比如 AutoGen、LangChain 等）？LangGraph 和 LangChain 是什么区别？

**短答**：先按任务控制需求选择抽象层。LangChain 提供模型、工具与 Agent 工厂，LangGraph 提供显式状态编排；项目需要审批、异常分支和恢复时采用自定义图。

**追问**：框架版本变化会怎样影响这个选型理由？

**正文**：[[04_工程与框架/10_主流Agent框架对比]]。

## ToB 场景下设计 Agent 架构，会主要从哪些方面去考虑？

**短答**：先定义业务成功条件，再设计权限、动作范围、可恢复状态、预算、可观测性与评测。自主程度随风险和验证能力调整，避免只比较框架功能清单。

**追问**：哪些动作必须在运行时独立校验？

**正文**：[[03_Agent系统/00_项目总览]]。

## MCP 的传输为何从旧双端点演进到 Streamable HTTP？

**短答**：旧 HTTP+SSE 是双端点路线；Streamable HTTP 使用统一 MCP endpoint，可继续使用 SSE。业务页面的 SSE 推流与 MCP 传输是不同用途。

**追问**：协议版本、传输方式与服务端授权如何分别理解？

**正文**：[[03_Agent系统/09_MCP协议与服务封装]]。

## 业界测试 Agent 能力的时候有哪些 Benchmark？

**短答**：按任务类型选择公开 Benchmark，例如软件工程、浏览器操作、通用助手和工具交互；项目还需要自己的任务集、安全场景与环境校验。不能只看一个公开总分。

**追问**：公开能力得分为什么不能直接预测项目成功率？

**正文**：[[03_Agent系统/07_Agent评测体系设计]]。

## Agent 记忆管理如何进行剪枝和压缩？

**短答**：保存历史与构造本次上下文是两回事。按 token 预算保留近期消息，压缩较早信息，保留工具调用配对；大日志提取关键字段，重要原始资料仍可追溯。

**追问**：摘要引入错误后如何检查与恢复？

**正文**：[[03_Agent系统/05_记忆与上下文管理]]。

## 如何衡量 Multi-agent 的性能和准确率？评估方法是怎样的？

**短答**：比较端到端任务成功、各 Worker 结果、协调成本、延迟和恢复情况；验证并行收益与隔离是否成立。最终汇总正确不能掩盖缺失 Worker 或未执行动作。

**追问**：多 Agent 相比单 Agent 的增益如何做消融？

**正文**：[[03_Agent系统/07_Agent评测体系设计]]。

## 线程状态与跨线程记忆如何区分？

**短答**：线程状态负责当前任务，checkpointer 保存恢复点；Store/namespace 管理跨线程可访问的记忆。数据库持久化与长期记忆不是同义词。

**追问**：命名空间本身是否提供身份认证？

**正文**：[[03_Agent系统/05_记忆与上下文管理]]。

## 当前 Agent 框架有哪些不同职责与维护状态？

**短答**：按控制流、恢复、数据接入、工具执行和运维比较，并记录版本与维护状态。对历史项目解释当时约束，对新项目重新验证候选路线。

**追问**：为什么不能把某个历史版本的限制推广到整个框架？

**正文**：[[04_工程与框架/10_主流Agent框架对比]]。

## 如何分别评测结果、轨迹、工具与成本？

**短答**：分别记录任务结果、工具与参数、执行轨迹、安全约束、延迟和每成功任务成本。使用同一次执行的真实轨迹，不能只给 Judge 最后一句回答。

**追问**：哪些指标可用断言，哪些确实需要 Judge？

**正文**：[[03_Agent系统/07_Agent评测体系设计]]。

## 工具 Schema、Message 与完整调用链如何对应？

**短答**：模型请求与工具结果通过调用 ID 关联，应用校验与执行后再反馈；消息历史应保留配对。Schema、工具契约和完整状态示例在各自正文维护。

**正文**：[[03_Agent系统/04_工具设计与完整调用示例]]。

## Agent 的测试用例怎样存储？

**短答**：区分完整用例、步骤、元数据和检索表示；用词法与语义索引按场景查找，执行记录和知识内容分别保存。专家许可执行不自动等于知识可入库。

**正文**：[[03_Agent系统/04_工具设计与完整调用示例]]。
