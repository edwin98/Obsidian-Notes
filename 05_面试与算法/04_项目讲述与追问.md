# 项目讲述与追问

本页维护表达结构、职责与追问；技术细节进入对应正文。项目事实分别见 [[02_RAG系统/01_项目事实与实现状态]]、[[03_Agent系统/01_项目事实与实现状态]]。

## RAG 项目的一分钟讲述

从业务中的专业资料查找问题开始，说明文档如何进入知识库、在线如何改写与混合检索、精排后怎样带引用生成。接着挑本人实际承担的两到三个模块，解释约束、方案选择和验证办法。最后引用事实表中有证据的结果；未确认数字不作为已完成成绩。

**追问**：为什么这样切片？为什么两级向量？如何发现漏召回、精排丢失和生成错误？为什么保留精确缓存而停用仅凭相似度复用答案？

**正文**：[[02_RAG系统/00_项目总览]]、[[02_RAG系统/04_查询改写与检索排序]]、[[02_RAG系统/05_答案生成与上下文管理]]。

## Agent 项目的一分钟讲述

先说测试需求、工具与真实执行环境，再讲模型决策、Guardrail、HITL、执行观察和独立判定。用一次正常流程和一次异常恢复证明对状态与动作的理解。区分设计方案、教学代码与生产实现，避免把训练参考脚本的预期值当成实测收益。

**追问**：如何暂停恢复？谁检查权限？工具超时如何处理？怎样防止重复执行？新用例生成到底到哪一步？

**正文**：[[03_Agent系统/00_项目总览]]、[[03_Agent系统/04_工具设计与完整调用示例]]、[[03_Agent系统/06_安全机制与异常恢复]]。

## 技术取舍怎样回答

按“业务约束 → 候选方案 → 选择理由 → 失败模式 → 验证依据”回答。三级检索候选数、模型与训练配置、数据规模统一查项目事实表，不从不同历史版本拼接答案。

## 难点与复盘怎样回答

选一个自己确实经历且能解释代码或实验的案例：HITL 等待与恢复、负样本误标、Chunk 截断、候选融合或权限过滤。说明原表现、定位过程、修改与验证。历史复盘素材见 [[02_RAG系统/07_检索模型微调总览与协同部署]]，工程学习见 [[03_Agent系统/code/学习指南]]。

## 团队分工与个人职责核对

系统涉及多个角色，分工边界如下：

**算法方向职责**（原笔记记录，实际个人承担范围需逐项核对）：
- Embedding 模型微调（数据集构建 + 训练 + 评测）
- Reranker 微调
- Chunk 算法设计（层次化切分策略、父子索引）
- 三级召回链路设计（粗筛/精筛/精排的指标实验）
- 评测系统设计（评测集构建、离线指标体系、E2E 评测流水线）

**后端工程师**：
- FastAPI 接口层、SSE 推流实现
- LangGraph 状态机工作流开发
- Kafka 消息总线、Celery 任务队列、Redis 缓存接入
- 离线入库 Pipeline 开发（Parser、Splitter、数据清洗模块）

**基础设施/运维**：
- Milvus、Elasticsearch 集群部署与运维
- Kafka、Redis 集群管理
- vLLM 推理服务部署与扩缩容

**产品/业务方**：
- 提供真实问答日志作为训练数据来源
- 参与 Golden Case 的业务验收
- 反馈线上问题，驱动迭代方向

**领域专家（无线工程师）**：
- 无线领域词表的人工校正（AutoPhrase 候选词审核）
- 边界 QA 样本的人工标注
- Reranker 标注数据的 Calibration（专家一致性对齐）
